services:
  server:

      dockerfile: deploy/Dockerfile.server
    container_name: topgun-server

    environment:
      RUST_LOG: topgun_server=info

# Self-host the server

Run the TopGun server on your own infrastructure using Docker, Docker Compose, or Kubernetes. The server keeps its data in an embedded store ([redb](https://github.com/cberner/redb)) inside the process — there is no database to run and no external dependency. Give it a persistent volume and your data survives restarts.

## Backup and restore

The data is two things on the volume: the redb file (`TOPGUN_REDB_PATH`, `/data/topgun.redb` in the image) and the write-ahead log directory (`TOPGUN_WAL_DIR`, `/data/topgun-wal` in the image). Acknowledged writes that are not yet in the redb file live in the WAL directory, so a backup needs both.

- **Back up:** stop the server (`SIGTERM`; it drains its write buffer and syncs the log, then exits 0), then copy the redb file and the WAL directory.
- **Restore:** with the server stopped, put both back, then start it.
- **Not supported:** a copy of a running server's files.

## Kubernetes

## TLS

<div className="flex items-center gap-2 mb-4 not-prose">
  <Lock className="w-6 h-6 text-green-600" />
  <span className="text-neutral-600 dark:text-neutral-300">The server binary does not read any <code>TOPGUN_TLS_*</code> environment variables today.</span>
</div>

The binary reads zero `TOPGUN_TLS_*` env vars (verified: 22 `std::env::var()` call sites, none matching `TOPGUN_TLS`). TLS is configured programmatically via `TlsConfig` when embedding the server in a Rust host process. See [Server & CLI reference — embed API](/docs/reference/server) for the programmatic approach.

**For standard production deployments,** terminate TLS at a reverse proxy in front of the server:

- **nginx** — `proxy_pass http://topgun-server:8080` with `ssl on` on the nginx listener
- **Caddy** — `reverse_proxy topgun-server:8080` under a `tls` directive
- **AWS ALB** — HTTPS listener with target group pointing at port 8080; ALB handles TLS offload

WebSocket connections (`ws://`) are proxied as-is; the proxy upgrades `wss://` externally.

## Serverless

<div className="flex items-center gap-2 mb-4 not-prose">
  <Cloud className="w-6 h-6 text-indigo-600" />

The Rust server is a long-running process that maintains in-memory CRDT state, WebSocket connections, and cluster membership. It does not support Vercel Edge Functions, AWS Lambda, or Cloudflare Workers.

Deploy TopGun as a persistent service (Docker, Kubernetes, or any platform supporting long-running processes) and connect from your edge functions using the TopGun client SDK:
