PART IV -- A PRE-DATA BUILDER DEFECT FOUND AND FIXED (R6.3's own point)
================================================================================

While exercising dry-run leg 2, `spec357-classify.sh`'s `drained_healthy_kind` and
`unclassified_exit` jq terms compared `exit_kind_variant` against the PascalCase Rust
source spellings `"DrainedByPrune"` / `"Unclassified"`. `EpochExitKind` carries
`#[serde(rename_all = "camelCase")]` (tombstone_frontier.rs), which serde applies to
unit-variant TAGS as well as field names, so the record actually serializes those tags
as `"drainedByPrune"` / `"unclassified"` -- confirmed empirically from Arm 1's own
entry/residency JSONL above. Under the unfixed comparison, EVERY real `DrainedByPrune`
exit would have been misclassified as class (c) FRONTIER RACE instead of class (d)
DRAINED-HEALTHY (Arm 1's first run, before the fix, showed exactly this: epoch 100001
read `class_c=1` where it should have read `class_d=1`), and `unclassified_exit` would
never have been set at all.

This is precisely the class of defect R6.3 exists to catch and R0.1's carry table
licenses fixing HERE, "where fixing it is free": "a count outside its band is RED in
the PRE-DATA wave, which is where a builder defect is free to fix." `spec357-
classify.sh` is this half's own G3 artifact (not one of the pinned, no-edit sidecars
named in the Constraints ledger), so the fix is in scope for this segment. Fixed by
comparing against the camelCase-serialized tags instead, with a WHY-comment recording
the reason. Re-run confirmed the correct per-class distribution (PART I, Arm 1).
