spec366 — the release build is not reproducible (raw observations)
==================================================================

Why this file exists
--------------------
Manifest §1 states that byte-identity cannot establish provenance for this spec, because the
release build does not map source to bytes as a function. That is a load-bearing claim: it is the
reason cell attempt 2 could not be carried across the freeze move from a18e09de to 3a009e42, and
the reason attempt 3 was run instead. The claim was substantiated from runner logs that live in a
scratch directory and do not survive, so the observations are recorded here, committed beside the
manifest, rather than cited to a path that will be gone.

What was being tested
---------------------
Conductor rulings v7 R1.2 proposed option (b'): fix the two doc sentences in crdt.rs with each
comment block's line count preserved, rebuild, and if the binary is byte-identical to the one the
cell measured, provenance holds by identity rather than by ancestry. Comments are not compiled and
no code line moved (5 insertions / 5 deletions, file length 9146 unchanged, hunks -751,3 +751,3 and
-1938,2 +1938,2), so identity was a reasonable expectation.

  bytewise, not merely by digest.

Conclusion
----------
Builds 4 and 5 share commit, path, command and cleaning procedure, and differ. So the release
profile (lto, codegen-units=1, strip=symbols) is not reproducible even at a fixed path; observed
output alternates between two values. Byte-identity presupposes that source -> bytes is a function,
so option (b') is unavailable in principle here, not merely unlucky.

It follows that build 4 matching the measurement is a COINCIDENCE of that alternation and is not
evidence of provenance: the same commit also yields 5c666185. Preserving comment line counts is
necessary but nowhere near sufficient.

Provenance therefore rests on MEASUREMENT, which survives non-determinism: the runner asserts, before
the clock, that the binary contains this branch's counter string and was built by this invocation,
and records its sha256 as the first line of the console log. That says WHICH binary produced the
numbers, which is the question identity was only ever a proxy for.

How to re-check
---------------
  cd <repo>; git checkout 3a009e42
  rm -f target/release/topgun-server && cargo clean -p topgun-server --release
  cargo build --release --bin topgun-server -p topgun-server && shasum -a 256 target/release/topgun-server
  # repeat the three lines above; the digest is expected to differ between runs.
